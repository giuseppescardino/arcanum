# Browser Extension Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome/Opera/Safari extension that fills saved logins, suggests generated passwords and saves new or changed logins, served by the running desktop app over an end-to-end-encrypted loopback channel.

**Architecture:** A pure Rust crate (`arcanum-bridge`) holds the pairing and envelope crypto and is exposed to Dart through the existing FFI crate. The desktop app runs a `dart:io` HTTP server on `127.0.0.1` that decrypts requests and answers them from `VaultController`. A single MV3 extension in plain JavaScript (WebCrypto) talks to that server. Safari gets an Xcode wrapper generated by `safari-web-extension-converter`.

**Tech Stack:** Rust (`p256` 0.13, `aes-gcm` 0.10, `hkdf` 0.12, `sha2` 0.10), flutter_rust_bridge 2.13.0, Flutter/Dart (`dart:io` `HttpServer`, `flutter_secure_storage`), JavaScript ES modules with `node --test` (Node 26), Xcode 26.

**Spec:** `docs/superpowers/specs/2026-11-11-browser-extension-design.md`

## Global Constraints

- Server binds `127.0.0.1` only. Ports are tried in the order 47613, 47614, 47615, and the extension probes the same list.
- Endpoint `POST /v1`, JSON body ≤ 64 KiB. Reject when `Host` ≠ `127.0.0.1:<port>`. Reject when `Origin` is present and starts with neither `chrome-extension://` nor `safari-web-extension://`.
- Labels, verbatim: `pm/bridge-pair/v1`, `pm/bridge-key/v1`, `pm/bridge-code/v1`, `pm/bridge-req/v1`, `pm/bridge-res/v1`.
- Pairing window 120 s; one pending pairing; verification code is 6 digits.
- Replay window ±60 s on `ts`, with seen `id`s remembered for that window.
- AES-256-GCM, 12-byte random nonce; wire format `b64(nonce ‖ ciphertext ‖ tag)` (standard base64 with padding everywhere).
- Generated password: length 20, lowercase, uppercase, digits and symbols on, avoid_ambiguous off.
- Pending save kept for 120 s in `chrome.storage.session`.
- The server runs only on macOS and Windows. `unsafe_code = "forbid"` applies to the new crate.
- UI copy is Italian (`app_it.arb`) with English in `app_en.arb`. Extension copy is Italian.
- Extension scope v1: top frame only, no fill on load, logins only, no cross-domain credentials.

## Review Focus

1. **Two-step logins** (the username on one page, the password on the next): submit captures an empty username. `check`/`save` must accept `username: ""` and still save. Covered by a test in Task 3.
2. **Non-http(s) tab URLs** (`chrome://`, `about:blank`, `file://`): `list` returns `[]`, and `save` returns `{"error":"bad_request"}` without crashing. Tests in Task 3 and Task 6.
3. **A foreign service on 47613**: the extension must skip a port whose `hello` reply is not `{"app":"arcanum"}` and try the next. Test in Task 6.
4. **The vault locks between "check" and clicking *Salva*** in the banner: the reply is `locked`, the pending entry must stay, and the banner switches to "Sblocca Arcanum". Test in Task 7 (background routing).
5. **URLs with ports and `www.`** (`http://localhost:3000`, `https://www.example.com/login`): host matching ignores the port and the `www.` prefix, as `hostOf` already does. Test in Task 3.

### Task 1: `arcanum-bridge` crate

**Files:**
- Create: `core/arcanum-bridge/Cargo.toml`, `core/arcanum-bridge/src/lib.rs`, `src/pairing.rs`, `src/envelope.rs`, `src/replay.rs`
- Create: `core/arcanum-bridge/tests/vectors.rs` (writes `extension/test/vectors.json`)
- Modify: `core/Cargo.toml` (member + workspace deps `p256 = { version = "0.13", features = ["ecdh"] }`, `aes-gcm = "0.10"`)

**Interfaces:**
- Produces:
  - `pub struct EphemeralKey` with `EphemeralKey::generate() -> Self` and `public_sec1(&self) -> [u8; 65]`.
  - `pub fn derive(own: EphemeralKey, ext_pub: &[u8], app_pub: &[u8], peer: &[u8]) -> Result<Paired, BridgeError>`, where `Paired { key: Zeroizing<[u8; 32]>, code: String }`. For determinism in tests, `derive_from_secret(own_scalar: &[u8; 32], …)`.
  - `pub enum Direction { Request, Response }`.
  - `pub fn seal(key: &[u8; 32], client: &str, dir: Direction, plaintext: &[u8]) -> String` (base64) and `seal_with_nonce(…, nonce: [u8; 12])` for vectors.
  - `pub fn open(key: &[u8; 32], client: &str, dir: Direction, b64: &str) -> Result<Vec<u8>, BridgeError>`.
  - `pub struct ReplayGuard` with `new(window_ms: i64)` and `check(&mut self, id: &str, ts: i64, now: i64) -> Result<(), BridgeError>`.
  - `BridgeError { InvalidKey, Decrypt, Replay, Stale }`.
- The AAD is `label bytes ‖ client bytes`. `th = SHA-256(label_pair ‖ ext_pub ‖ app_pub)`. The code is `u32::from_be_bytes(okm4) % 1_000_000`, formatted `{:06}`.

  - `mitm_changes_code`: ext↔mallory and mallory↔app codes differ.
